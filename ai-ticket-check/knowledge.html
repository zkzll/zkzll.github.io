05并发、分布式与高可用Concurrency, Distributed & High Availability
🔒
CAS 乐观锁
Compare-And-Swap — 所有状态流转（PENDING→RUNNING、RUNNING→SUCCESS 等）通过数据库 CAS 操作保证原子性。casReclaimStaleTask() 多实例安全回收僵死任务。避免分布式锁的性能开销。
🧵
弹性线程池
skillExecutor — core=4, max=16, queue=64, CallerRunsPolicy
CompletableFuture.runAsync() 异步调度 Agent 执行
主线程立即返回，Agent 在后台线程池执行，避免阻塞请求
🔄
幂等性设计
createAndStart() 通过 uk = taskScene + "#" + ticketId 做幂等校验，同一工单重复触发不会创建重复任务。CAS 操作天然幂等。
🔁
重试与容错
Agent 层面：429 / InvalidParameter / No ToolCallback — 最多重试 3 次
IdeasApiClient：瞬态 I/O 错误 — 最多重试 3 次
WatchDog：僵死任务自动重跑 — 最多 3 次
MetaQ：消费失败返回 RECONSUME_LATER — RocketMQ 自动重试
📊
事务管理
@Transactional 保证 createTask 时主任务和子任务的原子性写入
CAS 状态流转 + DB 约束保证一致性，不依赖分布式事务
🐕
WatchDog 自愈机制
每 5 分钟扫描 RUNNING 状态且 updated_time > 20min 的任务
rerunCount < 3 → CAS 回收 → forceRerun → invokeSkill
rerunCount >= 3 → 强制失败 + 钉钉告警
积压 ≥ 5 个连续 2 周期 → 积压告警

面试高频追问 & 回答要点
Q1: 为什么选择 Multi-Agent 而不是单 Agent？
6 大业务域差异大（清关需要 HS Code 分类，揽收需要地址解析），单 Agent 工具集爆炸且 prompt 臃肿。Multi-Agent 实现域隔离，每个 Agent 专注少量工具，降低 LLM 选择空间，提升准确率。
Q2: CAS 乐观锁在高并发下会有大量失败吗？
CAS 适用于冲突概率低的场景。工单状态流转是串行的（同一任务不会并发修改），所以 CAS 几乎不会失败。多实例回收僵死任务时通过 CAS 保证只有一个实例抢到，比分布式锁更轻量。
Q3: Agent 调用工具出错了怎么办？
三层容错：① 工具内部重试（IdeasApiClient 3 次瞬态重试）② Agent 层重试（429/InvalidParameter 最多 3 次）③ WatchDog 兜底（僵死 20min 自动重跑，最多 3 次）。最终失败才强制终止 + 钉钉告警。
Q4: SKILL Self-Managed 和 MetaQ 模式有什么区别？
MetaQ 模式：引擎预建子任务 → 通过消息队列分发到 Java SubTaskExecutor 执行。SKILL 模式：Agent 运行时通过 MCP 工具自主创建/驱动子任务，LLM 决定执行顺序。智查场景用 SKILL 模式，因为 5 步流水线需要 LLM 动态判断是否继续。
Q5: 如何保证 Agent 不会无限循环？
① Prompt 明确约束 5 步流水线和终结条件（必须调 finish_main_task）② WatchDog 20min 超时检测 + 强制中断 ③ 弹性线程池队列有限（64），过载时 CallerRunsPolicy 反压 ④ 每个 step 有 finish/fail 出口。
Q6: 99.3% 置信率是怎么计算的？
置信率 = AI 处理且无需人工修正的工单数 / AI 处理的总工单数。通过 check_ret 字段标记 AI 处理结果是否正确，has_pending_human 标记是否经过人工介入。多维 SQL 统计支撑 FBI 报表。
Q7: 弹性线程池 CallerRunsPolicy 的风险是什么？
当队列满且线程数达上限时，调用线程（如 HTTP 请求线程）会直接执行 Agent 任务，导致接口超时或 MetaQ 消费阻塞。改进方案：使用 Semaphore 限流或改为 AbortPolicy + 快速失败响应。
Q8: MCP 相比直接函数调用有什么优势？
MCP 提供标准化的工具描述（JSON Schema）、发现机制和调用协议。Agent 无需硬编码工具列表，运行时动态发现可用工具。支持跨进程/跨语言调用，便于工具独立部署和版本管理。
Q9: 如何处理 LLM 的幻觉问题？
① RAG 检索真实业务知识增强上下文 ② 工具调用结果作为事实依据（而非 LLM 生成）③ evaluate_attribution / evaluate_speech 工具做结果校验 ④ 置信度不足时 suspend 挂起请求人工介入。
Q10: 系统如何水平扩展？
① 无状态 Facade 层可水平扩容 ② MetaQ 多 Consumer 并行消费 ③ CAS 操作多实例安全（WatchDog 回收互斥）④ 弹性线程池参数可按机器规格调整 ⑤ PolarDB 分库分表支撑数据量增长。
